# 사고 재발 방지 작업 요약

## 사고

- 주문이 없는 사용자의 `getUserOrders()`가 `null`을 반환해 프론트엔드가 중단됐고 고객 3명이 데이터 조회 오류를 겪었다.
- 코드에 빈 결과를 배열로 보장하는 테스트가 없었고, 머지 전에 테스트도 자동 실행되지 않았다.

## 적용한 변경

- `src/orders.js`: 주문이 없을 때도 DB의 빈 배열을 그대로 반환하도록 `null` 반환 분기를 제거했다.
- `test/orders.test.js`: 주문 0건이면 `[]`를 반환하는 회귀 테스트와, 주문이 있으면 조회 결과를 그대로 반환하는 테스트를 추가했다.
- `.github/workflows/test.yml`: pull request와 `main` push마다 `npm test`를 실행하도록 GitHub Actions를 추가했다.
- 기존 `AGENTS.md`의 `npm test` 실행 규칙은 충분하므로 별도 사고 절차나 승인 문서는 추가하지 않았다.

## 검증 결과

`npm test` 실행 결과 2개 테스트가 모두 통과했다.

## 저장소 설정에서 필요한 후속 조치

GitHub의 `main` 브랜치 ruleset에서 `test` 상태 체크를 필수로 지정해야 실패한 테스트가 있는 PR의 머지를 실제로 막을 수 있다. 이 설정은 레포 파일만으로 적용할 수 없다.
