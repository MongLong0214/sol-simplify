# 주문 조회 장애 재발 방지 요약

## 사고 원인

- `getUserOrders()`가 주문이 없는 사용자의 조회 결과를 `[]` 대신 `null`로 바꿔 반환했습니다.
- 배열을 기대하던 프론트엔드가 `null`을 처리하지 못해 고객 3명이 데이터 조회 오류를 겪었습니다.
- 작업 시작 시 실제 소스에도 이 `null` 반환 분기가 남아 있었습니다.

## 적용한 변경

- `src/orders.js`: 데이터베이스의 조회 결과를 그대로 반환하도록 수정했습니다. 주문이 0건이면 빈 배열 계약이 유지됩니다.
- `test/orders.test.js`: 다음 동작을 실행하는 회귀 테스트 2건을 추가했습니다.
  - 주문이 0건인 사용자는 `[]`을 반환한다.
  - 주문이 있는 사용자는 데이터베이스가 반환한 주문 목록을 그대로 반환한다.
- `.github/workflows/test.yml`: 모든 pull request와 `main` push에서 Node.js 24로 `npm test`를 실행하도록 추가했습니다.

## 검증 결과

- 수정 전 회귀 테스트: 실패, `null !== []`로 사고 경로 재현
- 수정 후 `npm test`: 2건 통과, 실패 0건
- GitHub Actions 워크플로 YAML 문법 검사: 통과

## 남은 저장소 설정

GitHub의 `main` 브랜치 ruleset 또는 branch protection에서 이 워크플로의 `test` 체크를 필수(required)로 지정해야 테스트를 통과하지 않은 merge를 실제로 차단할 수 있습니다. 현재 제공된 작업 사본에는 `.git`과 원격 저장소 정보가 없어 이 외부 설정은 적용하지 못했습니다.
