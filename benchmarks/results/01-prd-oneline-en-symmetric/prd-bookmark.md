# 게시글 북마크 기능 PRD

## 1. 개요

로그인 사용자가 게시글을 북마크하거나 해제하고, 마이페이지에서 자신이 북마크한 게시글 목록을 확인할 수 있게 한다.

## 2. 목표

- 로그인 사용자가 게시글에서 북마크를 추가·해제할 수 있다.
- 사용자의 북마크 상태가 계정에 저장되어 다시 방문해도 유지된다.
- 마이페이지에서 북마크한 게시글을 최신 북마크순으로 볼 수 있다.

## 3. 범위 제외

- 비로그인 사용자의 로컬 북마크
- 북마크 폴더, 태그, 메모, 공유
- 북마크 수 공개 및 인기 순위
- 알림 기능

## 4. 사용자 시나리오

1. 로그인 사용자가 게시글을 연다.
2. 비활성 상태의 `북마크` 버튼을 누르면 북마크가 저장되고 버튼이 활성 상태로 바뀐다.
3. 활성 상태의 버튼을 다시 누르면 북마크가 삭제되고 버튼이 비활성 상태로 바뀐다.
4. 사용자가 마이페이지의 `북마크` 영역에 들어가면 북마크한 게시글 목록을 확인할 수 있다.
5. 목록의 게시글을 누르면 해당 게시글로 이동한다.

## 5. 기능 요구사항

### 5.1 게시글 북마크 버튼

- 게시글 화면에 로그인 사용자에게만 `북마크` 버튼을 노출한다.
- 현재 사용자의 북마크 여부에 따라 활성/비활성 상태를 표시한다.
- 비활성 상태에서 클릭하면 북마크를 생성한다.
- 활성 상태에서 클릭하면 북마크를 삭제한다.
- 저장 또는 삭제 요청 중에는 중복 요청을 막기 위해 버튼을 비활성화한다.
- 요청이 실패하면 기존 상태를 유지하고 오류 메시지를 표시한다.
- 버튼에 `aria-pressed`를 적용해 선택 상태를 보조 기술에 전달한다.

### 5.2 마이페이지 북마크 목록

- 마이페이지에 `북마크` 영역을 추가한다.
- 현재 사용자가 북마크한 게시글만 표시한다.
- `bookmarks.created_at` 내림차순으로 정렬한다.
- 각 항목은 기존 게시글 목록 컴포넌트와 동일한 핵심 정보 및 게시글 링크를 사용한다.
- 북마크가 없으면 `북마크한 게시글이 없습니다.`를 표시한다.
- 삭제된 게시글은 목록에 표시하지 않는다.

## 6. 데이터 모델

기존 `posts` 테이블과 Supabase Auth의 `auth.users`를 사용하고 `bookmarks` 테이블 하나만 추가한다.

| 필드 | 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| `user_id` | `uuid` | PK, FK → `auth.users.id`, NOT NULL | 북마크한 사용자 |
| `post_id` | 기존 게시글 ID 타입 | PK, FK → `posts.id`, NOT NULL | 북마크한 게시글 |
| `created_at` | `timestamptz` | NOT NULL, DEFAULT `now()` | 북마크 시각 |

- 복합 기본 키 `(user_id, post_id)`로 중복 북마크를 방지한다.
- 사용자별 최신 북마크 조회를 위해 `(user_id, created_at DESC)` 인덱스를 생성한다.
- 사용자 또는 게시글 삭제 시 연결된 북마크를 `ON DELETE CASCADE`로 삭제한다.
- Row Level Security를 활성화하고 `SELECT`, `INSERT`, `DELETE`를 `auth.uid() = user_id`인 행에만 허용한다.

## 7. 클라이언트 및 데이터 흐름

- 기존 Supabase 클라이언트와 React Query를 사용하며 별도 상태 관리 계층은 추가하지 않는다.
- 북마크 상태 조회 키: `['bookmark', postId, userId]`
- 마이페이지 목록 조회 키: `['bookmarks', userId]`
- 추가는 `bookmarks`에 `{ user_id, post_id }`를 삽입하고, 해제는 동일한 두 키로 행을 삭제한다.
- mutation 성공 후 해당 게시글의 북마크 상태 쿼리와 마이페이지 북마크 목록 쿼리를 무효화한다.
- App Router의 기존 인증 및 라우팅 방식을 그대로 사용한다.

## 8. 완료 조건

- [ ] 로그인 사용자가 게시글에서 북마크를 추가할 수 있다.
- [ ] 같은 사용자가 같은 게시글을 중복 북마크할 수 없다.
- [ ] 페이지를 새로고침해도 북마크 상태가 유지된다.
- [ ] 로그인 사용자가 북마크를 해제할 수 있다.
- [ ] 마이페이지에 현재 사용자의 북마크만 최신 북마크순으로 표시된다.
- [ ] 마이페이지 항목에서 해당 게시글로 이동할 수 있다.
- [ ] 북마크가 없을 때 빈 상태 문구가 표시된다.
- [ ] 다른 사용자의 북마크는 조회·생성·삭제할 수 없다.
- [ ] 추가·해제 실패 시 잘못된 성공 상태가 남지 않는다.

## 9. 검증 항목

- `bookmarks`의 중복 삽입이 데이터베이스 제약으로 거부되는지 확인한다.
- RLS로 다른 사용자의 북마크 접근이 차단되는지 확인한다.
- 버튼의 초기 상태, 추가, 해제, 요청 실패를 확인한다.
- 마이페이지 목록의 사용자 필터, 정렬, 빈 상태, 게시글 이동을 확인한다.
