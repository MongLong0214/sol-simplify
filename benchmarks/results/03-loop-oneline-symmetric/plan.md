# 티켓 착수 검증 단순화 계획

## 목표

- 티켓 착수 판단 장애가 구현 작업 전체를 멈추지 않게 한다.
- 파일 수·티켓 수 `census pin`과 재측정 커밋을 없앤다.
- 착수 판단은 실제 업무 규칙만 남기고, 구현 세부사항을 고정하는 계약 테스트는 삭제한다.
- 새 기준값, 허용 오차, 승인 절차, 상시 이중 실행은 만들지 않는다.

## 먼저 내릴 결정

1. **착수 리졸버를 필수 게이트에서 제거한다.** 착수 여부는 티켓의 현재 상태와 명시적인 미해결 선행 티켓으로만 판단한다. 리졸버 오류나 일부 티켓의 잘못된 데이터가 다른 티켓의 착수를 막아서는 안 된다.
2. **`census pin`은 폐기한다.** 동적 pin, 범위 pin, 자동 재측정으로 대체하지 않는다. 전체 개수는 동작의 정확성을 증명하지 못한다.
3. **기존 리졸버와 1:1 호환되는 재작성은 하지 않는다.** 실제 호출자가 쓰는 입력·출력만 유지하고, 나머지 분기와 그 분기를 고정한 테스트를 함께 제거한다.

## 실행 순서

### 1. 즉시 작업 재개

- CI와 티켓 자동화에서 착수 리졸버를 `required` 조건과 후속 작업의 선행 조건에서 뺀다.
- 어제 멈춘 네 티켓은 각각의 상태와 명시적 선행 티켓만 확인해 착수 가능 여부를 다시 계산하고, 가능한 작업을 즉시 재개한다.
- 기존 제품 빌드·제품 테스트·보안 검사는 그대로 유지한다. 이번 변경은 티켓 착수 정책만 대상으로 한다.

완료 조건:

- 한 티켓의 판정 실패나 리졸버 실행 실패가 다른 티켓의 구현 작업을 멈추지 않는다.
- 네 티켓 각각에 착수 가능 또는 실제 미해결 선행 티켓이라는 구체적인 결과가 나온다. “전체 0건”은 허용하지 않는다.

### 2. `census pin` 완전 제거

- 저장된 파일 수·티켓 수 기준값, 개수 수집기, 비교 로직, 재측정 명령, 관련 CI 단계와 테스트를 삭제한다.
- 개수를 이용해 실제 검사를 빠뜨리지 않게 하려던 곳은 현재 발견된 대상을 순회해 각 대상을 직접 검증하도록 바꾼다. 총 개수 자체는 단언하지 않는다.
- 코드와 CI 설정에서 `census`, `pin`, `rebaseline` 및 기준값 파일 참조를 검색해 남은 호출 경로가 없는지 확인한다.

완료 조건:

- 유효한 파일이나 티켓 하나를 추가·삭제해도 기준값 수정이 필요하지 않다.
- 두 브랜치가 서로 다른 파일이나 티켓을 추가해도 공통 pin 파일에서 충돌하지 않는다.
- census 재측정 전용 산출물과 커밋 경로가 레포에 남지 않는다.

### 3. 착수 규칙을 최소 계약으로 축소

- 리졸버의 실제 호출 위치와 호출자가 소비하는 필드만 추적한다. 사용되지 않는 출력, 예외 규칙, 우선순위 계층은 보존 대상에서 제외한다.
- 판정 규칙을 다음 세 경우로 제한한다.
  - 열린 티켓이고 미해결로 명시된 선행 티켓이 없으면 착수 가능
  - 미해결로 명시된 선행 티켓이 있으면 해당 티켓 ID와 함께 착수 불가
  - 종료·취소된 티켓은 착수 대상 아님
- 누락되거나 읽을 수 없는 데이터는 그 티켓의 진단 오류로 반환한다. 이를 “착수 불가”로 바꾸거나 전체 목록을 빈 결과로 만들지 않는다.
- 정책상 필요하다고 입증되지 않은 규칙은 새 리졸버에 옮기지 않는다.

완료 조건:

- 위 세 규칙과 티켓별 오류 격리가 짧은 표 기반 테스트로 설명된다.
- 동일 입력은 동일 결과를 내며, 판정 과정에서 레포 전체 개수나 다른 무관한 티켓 상태를 읽지 않는다.

### 4. 리졸버와 계약 테스트 교체

- 최소 규칙을 순수 판정 함수로 구현하고, 꼭 필요한 호출자에만 얇은 입출력 어댑터를 둔다.
- 새 동작이 준비되면 5,745줄 리졸버의 이전 경로, 우회 경로, 사용되지 않는 어댑터를 삭제한다. 장기 이중 실행이나 기능 플래그는 두지 않는다.
- 8,683줄 계약 테스트에서 구현 분기, 출력 순서, 전역 개수, 대형 스냅샷을 고정하는 테스트를 삭제한다.
- 남길 테스트는 세 가지 업무 규칙, 여러 티켓의 독립 판정, 한 티켓의 잘못된 데이터가 나머지 결과를 지우지 않는 경우, 실제 호출 형식 한 건뿐이다.

완료 조건:

- 기존 호출자는 필요한 결과를 계속 받는다.
- 조건을 만족하는 티켓이 있는데도 전체 결과가 0건이 되는 회귀 테스트가 실패하지 않는다.
- 제거한 코드나 계약 테스트를 참조하는 스크립트·CI 단계가 없다.

### 5. 병합과 최종 확인

- 1단계와 2단계를 먼저 한 변경으로 병합해 차단과 pin 충돌을 끝낸다. 진행 중인 브랜치는 이 변경을 한 번만 반영한다.
- 이어서 3단계와 4단계의 리졸버 축소를 병합한다.
- 각 변경에서 기존 제품 테스트와 축소된 착수 판정 테스트를 실행하고, 깨끗한 체크아웃에서 CI가 census 기준값 없이 통과하는지 확인한다.
- 마지막으로 삭제량은 참고 수치로만 기록한다. 줄 수 목표나 새 크기 게이트는 만들지 않는다.

## 종료 기준

- 착수 리졸버는 구현 작업의 필수 게이트가 아니다.
- census pin 및 재측정 절차가 없다.
- 동시 브랜치가 전역 개수 기준값 때문에 충돌하지 않는다.
- 착수 불가 결과에는 항상 해당 티켓의 실제 상태 또는 미해결 선행 티켓이 제시된다.
- 검증 코드는 제품 동작을 검증하며, 레포의 모양이나 검증 구현 자체를 보호하지 않는다.
