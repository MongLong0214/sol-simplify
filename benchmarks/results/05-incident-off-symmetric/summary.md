## 이번에 적용한 조치

1. **반환 계약 수정** (`src/orders.js`)
   - 주문이 0건이어도 `getUserOrders()`가 항상 배열을 반환하도록 `null` 분기를 제거함.
   - 호출자가 반환값을 안전하게 순회할 수 있다는 계약을 주석으로 명시함.

2. **회귀 테스트 추가** (`test/orders.test.js`)
   - 주문이 0건일 때 정확히 빈 배열을 반환하고 `map()` 호출이 실패하지 않는지 검증함.
   - 주문이 존재할 때 DB 결과를 그대로 반환하는 기존 동작도 함께 검증함.
   - 쿼리가 사용자 ID를 파라미터로 전달하는지도 검증함.

3. **PR/메인 브랜치 CI 추가** (`.github/workflows/test.yml`)
   - 모든 pull request와 `main` 푸시에서 `npm test`를 실행함.
   - 수동 실행도 가능하게 했으며, 중복 실행 취소와 5분 타임아웃을 설정함.
   - 워크플로 권한을 읽기 전용으로 제한함.

4. **머지 절차 명문화** (`AGENTS.md`, `.github/pull_request_template.md`)
   - 동작 변경에는 테스트를, 버그 수정에는 수정 전 실패하는 회귀 테스트를 요구함.
   - 로컬 `npm test` 실행, 빈 값/누락 값/오류 반환 계약 확인, CI 통과 여부를 PR 체크리스트에 추가함.
   - 필수 `test` CI가 통과하기 전에는 머지하지 않도록 저장소 작업 지침에 명시함.

## 저장소 관리자 후속 조치

CI 워크플로 파일만으로는 실패한 PR의 머지를 강제로 차단할 수 없다. GitHub 저장소 설정에서 `main` 브랜치 ruleset 또는 branch protection을 다음과 같이 설정해야 한다.

- pull request를 통해서만 변경 허용
- 필수 status check로 `test` 지정
- 최소 1명 승인 요구 및 새 커밋 시 기존 승인 무효화
- 필수 체크가 끝나기 전 머지 차단
- 관리자 우회와 `main` 직접 푸시를 허용하지 않음

이 설정까지 적용되면 이번 사고의 유입 경로였던 “테스트를 실행하지 않은 변경의 직접 머지”가 기술적으로 차단된다.
