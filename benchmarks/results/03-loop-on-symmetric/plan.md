# 검증 기계 축소 계획

## 판단

현재 검증 체계는 제품 결함보다 자체 규칙을 검증하는 순환 구조다. 리졸버와 계약 테스트만 14,428줄이고, 전체 검증 기계(20,280줄)가 제품 소스(17,964줄)보다 크다. 지난달의 pin 재측정 25건과 어제 중단된 구현 4건은 유지보수 불편이 아니라 구조적 실패다. 리졸버를 고치거나 예외 경로를 추가하지 말고, 티켓 착수 승인 권한을 검증 기계에서 제거한다.

가정: 이 리졸버와 census pin은 작업 절차만 검사하며 보안·데이터 무결성 같은 제품 안전 조건을 집행하지 않는다. 그런 조건이 섞여 있다면 아래 삭제 전에 제품 코드의 입력 검증이나 행동 테스트로 옮겨 보존한다.

## 실행 순서

1. **작업부터 복구한다.** 리졸버 게이트를 필수 CI·머지·티켓 실행 경로에서 제거하고, 멈춘 구현 4건을 다시 착수한다. 임시 우회 플래그, 예외 목록, 수동 승인 단계는 만들지 않는다.
2. **census pin을 삭제한다.** 파일 수·티켓 수의 저장값, 비교 로직, 갱신 스크립트와 관련 CI 실패 조건을 제거한다. 이 수치는 제품의 정확성을 증명하지 않고 병렬 브랜치끼리 충돌만 만든다. 대체 pin도 만들지 않는다.
3. **리졸버를 제거한다.** 호출 지점부터 끊은 뒤 5,745줄의 리졸버와 전용 설정을 삭제한다. 티켓 착수 여부는 담당자가 티켓 내용과 실제 의존성을 보고 판단하게 한다.
4. **계약 테스트를 분류해 정리한다.** 8,683줄 중 리졸버의 상태 전이, 티켓 메타데이터, 개수, 규칙 조합만 검증하는 테스트는 함께 삭제한다. 실제 사용자 동작, 보안, 데이터 손실 방지를 검증하는 사례가 있다면 해당 제품 모듈의 행동 테스트로 이동한다.
5. **남은 연결부를 청소한다.** CI 설정, 패키지 스크립트, 문서에서 삭제된 게이트·pin·리졸버 참조를 제거한다. 새로운 준비도 검사기나 동기화 장부는 추가하지 않는다.
6. **제품 기준으로 확인한다.** 기존 제품 테스트와 빌드를 실행하고, 멈췄던 4개 티켓이 별도 pin 갱신 없이 진행되는지 확인한다. 실패가 제품 동작과 무관한 절차 검사라면 그 검사도 제거한다.

완료 상태는 단순하다: 파일·티켓 개수가 머지를 막지 않고, 티켓 착수에 리졸버 승인이 필요 없으며, 필수 검사는 사용자에게 영향을 주는 제품 동작만 검증한다.
