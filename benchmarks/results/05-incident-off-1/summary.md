# 주문 조회 장애 재발 방지 요약

## 사고 요약

- 영향: 주문이 없는 고객 3명이 데이터 조회 오류를 경험했다.
- 직접 원인: `getUserOrders()`가 주문이 0건일 때 배열 대신 `null`을 반환했고, 배열을 기대한 프론트엔드가 이를 처리하지 못했다.
- 프로세스 원인: 해당 변경이 자동 테스트 없이 머지됐다.
- 초기 조치: 원인 커밋은 이미 revert됐다. 다만 작업 시작 시점의 `src/orders.js`에도 빈 결과를 `null`로 바꾸는 분기가 남아 있어 함께 제거했다.

## 적용한 변경

1. 반환 계약 수정 (`src/orders.js`)
   - 데이터베이스가 반환한 빈 배열을 그대로 반환하도록 `null` 변환 분기를 제거했다.
   - 이제 주문이 없는 정상 상태도 다른 조회 결과와 동일하게 배열로 처리된다.

2. 회귀 테스트 추가 (`test/orders.test.js`)
   - 주문이 0건인 사용자의 결과가 `[]`이며 배열 타입인지 검증한다.
   - 주문이 있는 사용자의 결과가 손실이나 변형 없이 반환되는지도 검증한다.
   - 쿼리와 사용자 ID 파라미터도 함께 확인한다.

3. PR 자동 테스트 추가 (`.github/workflows/test.yml`)
   - 모든 pull request에서 `npm test`를 실행한다.
   - `main`에 반영된 뒤에도 테스트를 실행해 기본 브랜치 상태를 계속 확인한다.
   - 워크플로 권한을 읽기 전용으로 제한하고, 중복 실행을 취소하며, 5분 타임아웃을 설정했다.

4. PR 체크리스트 추가 (`.github/pull_request_template.md`)
   - 테스트 실행, 경계 사례 검증, 반환 타입/API 계약의 호출자 영향 확인을 리뷰 전에 명시적으로 점검하도록 했다.
   - 배포 위험, 모니터링 지표, 롤백 방법을 PR에 기록하도록 했다.

## 검증 결과

- 실행 명령: `npm test`
- 결과: 테스트 2건 통과, 실패 0건
- 추가 확인: `src/orders.js`와 `test/orders.test.js` 모두 `node --check` 통과

## 저장소 관리자 후속 조치

CI 파일만 추가해서는 실패한 PR의 머지를 완전히 차단할 수 없다. GitHub의 `main` 브랜치 규칙에서 다음 항목을 설정해야 한다.

- pull request를 통해서만 변경 허용
- `npm test` 상태 체크를 필수(required)로 지정
- 필수 체크가 최신 커밋에서 통과해야 머지 허용
- 관리자 및 우회 권한 보유자에게도 규칙 적용

이 설정까지 완료하면 테스트가 없거나 회귀 테스트가 실패한 변경이 `main`에 머지되는 경로를 차단할 수 있다.
