# 게시글 북마크 기능 PRD

## 1. 개요

로그인 사용자가 게시글을 북마크하거나 해제하고, 마이페이지에서 자신이 북마크한 게시글을 다시 찾을 수 있도록 한다.

가정: 이번 범위의 북마크 버튼은 게시글 상세 화면에 제공한다. 게시글 목록 카드까지 버튼을 확장하는 것은 범위에 포함하지 않는다.

## 2. 목표

- 로그인 사용자가 한 번의 동작으로 게시글을 북마크하거나 해제할 수 있다.
- 사용자가 마이페이지에서 자신의 북마크 목록을 최신 북마크순으로 확인하고 게시글로 이동할 수 있다.
- 사용자별 북마크 데이터가 중복되거나 다른 사용자에게 노출·변경되지 않는다.

## 3. 사용자 흐름

### 게시글에서 북마크하기

1. 로그인 사용자가 게시글 상세 화면에 진입한다.
2. 현재 사용자의 북마크 여부에 따라 버튼이 `북마크` 또는 `북마크 해제` 상태로 표시된다.
3. 사용자가 버튼을 누르면 상태가 즉시 전환되고 서버에 저장된다.
4. 저장에 실패하면 이전 상태로 복구하고 재시도 가능한 오류 메시지를 보여준다.

비로그인 사용자가 버튼을 누르면 로그인 화면으로 이동하되, 로그인 후 원래 게시글로 돌아올 수 있어야 한다.

### 마이페이지에서 확인하기

1. 로그인 사용자가 마이페이지의 `북마크` 영역에 진입한다.
2. 북마크한 게시글이 최근 북마크한 순서로 표시된다.
3. 항목을 선택하면 해당 게시글 상세 화면으로 이동한다.
4. 북마크가 없으면 빈 상태 안내를 표시한다.

## 4. 기능 요구사항

### 북마크 버튼

- 게시글별 현재 북마크 여부를 정확히 표시한다.
- 북마크 추가와 해제를 지원한다.
- 동일한 사용자가 같은 게시글을 두 번 북마크할 수 없다.
- 요청 처리 중에는 중복 요청을 막고, 성공 시 관련 게시글 및 마이페이지 북마크 쿼리를 최신화한다.
- 이미 추가된 북마크의 재추가와 이미 삭제된 북마크의 재삭제는 오류 없이 같은 최종 상태를 반환한다.
- 실패 시 낙관적으로 변경한 UI를 원래 상태로 되돌리고 사용자에게 오류를 알린다.

### 마이페이지 북마크 목록

- 현재 로그인한 사용자의 북마크만 조회한다.
- 각 항목에는 서비스의 기존 게시글 카드에 필요한 정보(예: 제목, 작성자, 작성일)를 표시한다.
- 목록은 `bookmarks.created_at` 내림차순으로 정렬한다.
- 목록이 길어질 수 있으므로 기존 서비스의 목록 방식에 맞춰 페이지네이션 또는 무한 스크롤을 적용한다.
- 삭제되었거나 현재 사용자가 열람할 수 없는 게시글은 목록에 노출하지 않는다.
- 로딩, 빈 목록, 조회 실패 상태를 각각 제공한다.

## 5. 데이터 및 서버 계약

Supabase에 다음 관계를 갖는 `bookmarks` 테이블을 추가한다.

| 컬럼 | 타입 | 조건 |
| --- | --- | --- |
| `user_id` | `uuid` | `auth.users.id` 참조, `NOT NULL` |
| `post_id` | 게시글 PK와 동일 | `posts.id` 참조, `NOT NULL` |
| `created_at` | `timestamptz` | `NOT NULL`, 기본값 `now()` |

- 기본 키 또는 유니크 제약: `(user_id, post_id)`
- 목록 조회 인덱스: `(user_id, created_at DESC)`
- 게시글 삭제 시 연결된 북마크도 삭제되도록 외래 키 정책을 설정한다.

Next.js App Router의 Route Handler에서 인증된 Supabase 세션을 기준으로 다음 동작을 제공한다. 클라이언트가 전달한 `user_id`는 신뢰하지 않는다.

- 북마크 상태 조회
- 북마크 추가
- 북마크 해제
- 현재 사용자의 북마크 목록 조회

목록 응답에는 다음 페이지 조회에 필요한 커서와 게시글 표시 데이터를 포함한다. 존재하지 않거나 열람 권한이 없는 게시글에는 북마크를 생성할 수 없다.

## 6. 인증 및 권한

- Supabase Row Level Security를 활성화한다.
- 사용자는 `auth.uid() = user_id`인 행만 조회, 추가, 삭제할 수 있다.
- 추가 시 서버 세션의 사용자 ID를 사용한다.
- 게시글 자체의 공개 범위 또는 열람 권한도 함께 검증한다.
- 마이페이지와 변경 API는 미인증 요청에 인증 필요 응답을 반환한다.

## 7. 클라이언트 상태 관리

- React Query로 북마크 상태와 마이페이지 목록을 관리한다.
- 추가·해제 시 낙관적 업데이트를 적용하고, 실패 시 롤백한다.
- 성공 후 해당 게시글의 북마크 상태와 마이페이지 북마크 목록 쿼리를 무효화한다.
- App Router에서 서버 프리패치를 사용한다면 인증된 사용자 데이터만 `dehydrate`하고, 사용자 간 캐시가 공유되지 않도록 한다.

## 8. UI 및 접근성

- 아이콘만 사용하더라도 버튼에 `북마크 추가` 또는 `북마크 해제`라는 접근 가능한 이름을 제공한다.
- 선택 상태는 색상만으로 구분하지 않고 아이콘 형태 또는 텍스트로도 표현한다.
- 키보드로 버튼을 조작할 수 있고 포커스 표시가 보여야 한다.
- 상태 변경 결과와 오류 메시지는 스크린 리더가 인지할 수 있어야 한다.

## 9. 수용 조건

- 로그인 사용자가 게시글을 북마크하면 새로고침 후에도 선택 상태가 유지된다.
- 같은 버튼을 다시 누르면 북마크가 해제되고 마이페이지 목록에서도 사라진다.
- 같은 게시글에 대한 중복 북마크 행이 생성되지 않는다.
- 마이페이지에는 현재 사용자의 북마크만 최신 북마크순으로 표시된다.
- 비로그인 사용자는 북마크 변경이나 마이페이지 목록 조회를 할 수 없다.
- 다른 사용자의 북마크 행을 조회하거나 변경하려는 요청은 거부된다.
- 네트워크 또는 서버 오류 시 UI가 잘못된 선택 상태로 남지 않는다.
- 삭제되거나 열람 권한이 없는 게시글은 북마크 목록에서 노출되지 않는다.

## 10. 범위 제외

- 북마크 폴더, 태그, 메모
- 북마크 공개 및 공유
- 북마크 수 노출이나 인기 순위
- 알림, 추천, 오프라인 저장
- 게시글 목록 카드의 북마크 버튼
