# 프로필 사진 업로드 스펙

## 목표

로그인한 사용자가 자신의 프로필 사진을 업로드하거나 교체하고, 저장 직후와 이후 방문에서 새 사진을 볼 수 있게 한다.

가정: 로그인, 사용자 프로필, 프로필 편집 화면은 이미 존재한다.

## 사용자 흐름

1. 프로필 편집 화면에서 이미지 파일을 선택한다.
2. 선택한 이미지를 원형 아바타 형태로 미리 본다.
3. 저장하면 업로드 진행 상태를 표시하고 중복 저장을 막는다.
4. 성공 시 화면의 모든 사용자 아바타를 새 이미지로 갱신한다.
5. 실패 시 기존 사진을 유지하고, 원인과 재시도 방법을 안내한다.

## 요구사항

- JPEG, PNG, WebP 이미지를 지원한다.
- 파일 크기는 서비스의 업로드 제한을 따르며, 초과 파일은 업로드 전에 가능하면 차단한다.
- 서버는 확장자가 아니라 실제 파일 내용으로 이미지 형식을 검증한다.
- 서버가 이미지를 디코딩한 뒤 안전한 형식으로 다시 저장하고 위치 정보 등 메타데이터를 제거한다.
- 사진은 인증된 사용자 본인의 프로필에만 연결할 수 있다.
- 새 사진의 저장과 프로필 연결이 모두 성공한 뒤 기존 사진을 제거한다. 실패하면 기존 사진을 보존한다.
- 사진이 없을 때는 기존 기본 아바타를 표시한다.
- 브라우저 캐시 때문에 이전 사진이 남지 않도록 새 URL 또는 버전 값을 사용한다.

## 서버 계약

`PUT /api/me/avatar`

- 인증 필수
- 요청: `multipart/form-data`, 필드명 `file`
- 성공: `200 { "avatarUrl": "..." }`
- 잘못된 파일: `400` 또는 `415`
- 업로드 제한 초과: `413`
- 인증 실패: `401`

저장소에는 생성된 객체 키를 사용하고, 사용자 레코드에는 공개 URL 대신 해당 키를 연결한다. 응답 URL은 현재 저장소의 공개 또는 서명 URL 정책으로 만든다.

## 화면 및 접근성

- 파일 선택 버튼은 키보드로 조작할 수 있고 명확한 레이블을 가진다.
- 미리보기에는 사용자 이름 기반의 대체 텍스트를 제공한다.
- 진행 상태와 오류 메시지는 보조 기술에도 전달한다.
- 클라이언트 미리보기와 실제 저장 이미지는 같은 비율로 표시한다. 자르기 UI는 제공하지 않고 중앙 맞춤으로 보여준다.

## 완료 조건

- 유효한 이미지를 저장하면 즉시 새 아바타가 보이고 새로고침 후에도 유지된다.
- 기존 사진이 있는 사용자는 같은 흐름으로 교체할 수 있다.
- 지원하지 않거나 손상되거나 제한을 초과한 파일은 저장되지 않으며 기존 사진이 유지된다.
- 다른 사용자의 프로필 사진을 변경하는 요청은 허용되지 않는다.
- 업로드 도중 네트워크 오류가 발생해도 다시 시도할 수 있다.

## 제외 범위

사진 삭제, 자르기·회전·필터, 카메라 촬영, 콘텐츠 검수는 이번 구현에 포함하지 않는다.
