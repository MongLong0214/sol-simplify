# CI 품질 게이트

첫 CI는 실제 결함을 막는 두 가지 검사만 필수로 둔다. 모든 검사는 로컬에서도 같은 `package.json` 스크립트로 실행할 수 있어야 한다.

## 실행 조건

- pull request와 기본 브랜치 push에서 실행한다.
- 레포의 lockfile에 맞는 고정 설치 명령(`npm ci`, `pnpm install --frozen-lockfile` 등)을 사용한다.
- 프로젝트가 지원하는 Node.js 버전 하나로 시작한다. 버전 매트릭스는 여러 버전을 실제로 지원할 때만 추가한다.

## 필수 게이트

| 게이트 | 실행 | 실패 조건 |
| --- | --- | --- |
| 타입 검사 | `package.json`의 `typecheck` 스크립트. 없다면 `tsc --noEmit`에 해당하는 스크립트를 추가한다. | TypeScript 진단이 하나라도 발생함 |
| 테스트 | 기존 테스트 스크립트(예: `npm test`) | 테스트 실패, 테스트 실행 오류, 비정상 종료 |

두 게이트는 병렬 실행해도 된다. 어느 하나라도 실패하면 CI 전체를 실패 처리한다.

## 조건부 게이트

- **빌드:** 배포물이나 배포용 번들을 만드는 패키지라면 `build`를 필수 게이트에 추가한다. 타입 검사만으로 발견되지 않는 번들링·패키징 오류를 막는다.
- **린트:** 이미 린터가 설정되어 있고 오류 규칙이 실제 버그를 잡는다면 기존 `lint` 스크립트를 추가한다. CI를 위해 새 스타일 규칙부터 도입하지는 않는다.

## 지금 넣지 않는 것

- 임의의 커버리지 하한선. 현재 기준과 놓친 결함 사례 없이 숫자를 정하면 테스트의 가치보다 수치 맞추기를 유도한다.
- 포맷 검사, 파일 수·테스트 수 같은 고정 카운트, 문서 형식 검사.
- 의존성 감사 결과의 일괄 차단. 별도 대응 기준 없이 켜면 조치 불가능한 경고가 배포를 막을 수 있다.
- 여러 OS·Node.js 버전 매트릭스. 실제 지원 범위가 정해진 뒤 추가한다.

게이트가 제품 결함과 무관한 이유로 반복 실패하면 예외 절차를 만들지 말고 해당 게이트를 수정하거나 제거한다.
