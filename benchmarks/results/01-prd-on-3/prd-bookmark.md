# 게시글 북마크 기능 PRD

## 1. 개요

로그인 사용자가 게시글을 북마크하거나 해제하고, 마이페이지에서 자신이 북마크한 게시글을 다시 확인할 수 있게 한다.

### 전제

- 게시글 상세 화면과 마이페이지가 이미 존재한다.
- 게시글 목록의 정렬·페이지네이션·노출 가능 여부는 기존 서비스 정책을 따른다.
- 실제 URL, 컴포넌트명, 게시글 ID 타입은 현재 코드베이스의 규칙을 따른다.

## 2. 목표

- 로그인 사용자는 게시글 상세 화면에서 북마크 상태를 확인할 수 있다.
- 로그인 사용자는 북마크를 추가하거나 해제할 수 있다.
- 로그인 사용자는 마이페이지에서 본인이 북마크한 게시글 목록을 볼 수 있다.
- UI 상태와 Supabase의 저장 상태가 실패 상황에서도 일치한다.

## 3. 제외 범위

- 북마크 폴더, 태그, 메모, 공유 기능
- 북마크 수 공개 및 인기 순위
- 북마크 알림
- 관리자용 북마크 관리 화면
- 비로그인 사용자의 로컬 북마크 저장

## 4. 사용자 흐름

### 4.1 북마크 추가

1. 로그인 사용자가 게시글 상세 화면을 연다.
2. 시스템이 해당 사용자의 북마크 여부를 표시한다.
3. 사용자가 `북마크` 버튼을 누른다.
4. 버튼이 선택 상태로 바뀌고 북마크가 저장된다.
5. 같은 게시글을 다시 북마크해도 중복 레코드는 생기지 않는다.

### 4.2 북마크 해제

1. 사용자가 선택 상태인 `북마크` 버튼을 누른다.
2. 버튼이 미선택 상태로 바뀌고 저장된 북마크가 삭제된다.
3. 마이페이지 북마크 목록에서도 해당 게시글이 제거된다.

### 4.3 북마크 목록 조회

1. 로그인 사용자가 마이페이지의 `북마크` 영역으로 이동한다.
2. 최근 북마크한 순서대로 게시글 목록을 본다.
3. 게시글을 선택하면 해당 게시글 상세 화면으로 이동한다.
4. 북마크가 없으면 빈 상태 안내를 본다.

### 4.4 비로그인 사용자

- 비로그인 사용자가 북마크 버튼을 누르면 로그인 필요 안내와 로그인 이동 수단을 제공한다.
- 로그인 완료 후에는 가능하면 원래 게시글로 돌아온다.
- 인증되지 않은 요청으로 북마크 데이터가 생성되거나 조회되어서는 안 된다.

## 5. 기능 요구사항

### 5.1 북마크 버튼

- 게시글 상세 화면에 북마크 버튼을 노출한다.
- 미선택/선택 상태를 아이콘과 텍스트 또는 접근 가능한 이름으로 구분한다.
- 저장 중 연속 클릭으로 중복 요청이 발생하지 않게 한다.
- React Query의 optimistic update를 사용할 경우 요청 실패 시 이전 상태로 되돌리고 재시도 가능한 오류 안내를 제공한다.
- 페이지 새로고침 후에도 Supabase에 저장된 상태가 유지되어야 한다.
- 게시글별 사용자 북마크는 하나만 존재해야 한다.

### 5.2 마이페이지 북마크 목록

- 현재 로그인한 사용자의 북마크만 조회한다.
- 기본 정렬은 `bookmarks.created_at DESC`이다.
- 각 항목은 기존 게시글 목록 UI와 동일한 핵심 정보 및 상세 링크를 사용한다.
- 기존 게시글 목록에 페이지네이션 또는 무한 스크롤이 있다면 같은 방식을 재사용한다.
- 목록에서 북마크를 해제할 수 있다면 성공 즉시 해당 항목을 제거한다.
- 삭제되었거나 현재 사용자에게 열람 권한이 없는 게시글은 목록에 표시하지 않는다.
- 결과가 없으면 `북마크한 게시글이 없습니다`와 게시글 탐색 이동 수단을 제공한다.
- 로딩, 오류, 빈 상태를 서로 구분한다.

### 5.3 데이터 동기화

- 북마크 추가/해제 성공 후 게시글 상세의 상태와 마이페이지 목록 캐시를 함께 갱신하거나 무효화한다.
- 동일 게시글을 여러 탭에서 변경한 경우 재조회 시 서버 상태로 수렴해야 한다.
- 네트워크 오류를 저장 성공으로 표시하지 않는다.

## 6. 데이터 모델

Supabase에 `bookmarks` 테이블을 추가한다.

| 컬럼 | 타입 | 제약 |
|---|---|---|
| `user_id` | `uuid` | `NOT NULL`, `auth.users.id` 외래 키, 사용자 삭제 시 `CASCADE` |
| `post_id` | `posts.id`와 동일 | `NOT NULL`, `posts.id` 외래 키, 게시글 삭제 시 `CASCADE` |
| `created_at` | `timestamptz` | `NOT NULL`, 기본값 `now()` |

- 기본 키 또는 유니크 제약: `(user_id, post_id)`
- 목록 조회용 인덱스: `(user_id, created_at DESC)`
- 수정할 값이 없으므로 `UPDATE` 동작은 제공하지 않는다.

## 7. 권한 및 보안

`bookmarks` 테이블에 RLS를 활성화하고 다음 원칙을 적용한다.

- `SELECT`: `auth.uid() = user_id`인 행만 허용
- `INSERT`: `auth.uid() = user_id`인 행만 허용
- `DELETE`: `auth.uid() = user_id`인 행만 허용
- 쓰기 요청의 사용자 ID는 클라이언트 입력을 신뢰하지 않고 인증 세션에서 결정한다.
- 브라우저에 Supabase service role key를 노출하지 않는다.
- 북마크 목록 조회 시 기존 게시글 열람 권한도 함께 만족해야 한다.

## 8. 서버 및 클라이언트 동작

- Next.js App Router의 기존 데이터 접근 방식에 맞춰 Route Handler 또는 Server Action 중 하나를 사용한다.
- 서버는 요청마다 Supabase 인증 세션을 검증한다.
- 북마크 추가는 중복 호출에도 최종 결과가 북마크 상태가 되도록 처리한다.
- 북마크 해제는 대상 행이 이미 없어도 최종 결과가 미북마크 상태가 되도록 처리한다.
- 클라이언트는 React Query로 북마크 상태와 목록 캐시를 관리한다.
- Query Key는 사용자별 데이터가 섞이지 않도록 사용자 식별 범위를 포함하거나 로그아웃 시 관련 캐시를 제거한다.
- 로그아웃 이후 이전 사용자의 북마크 상태나 목록이 화면에 남아서는 안 된다.

## 9. UI 및 접근성

- 북마크 버튼은 키보드로 초점을 받고 `Enter` 또는 `Space`로 실행할 수 있어야 한다.
- 토글 상태는 `aria-pressed` 등 보조기술이 이해할 수 있는 방식으로 전달한다.
- 아이콘만 사용하는 경우에도 `북마크 추가` 또는 `북마크 해제`라는 접근 가능한 이름을 제공한다.
- 선택 여부를 색상만으로 구분하지 않는다.
- 저장 중 상태와 오류 안내는 사용자에게 인지 가능해야 한다.

## 10. 오류 및 예외 처리

- 인증 만료: 로그인 필요 상태로 전환하고 저장 성공으로 표시하지 않는다.
- 존재하지 않거나 삭제된 게시글: 북마크를 생성하지 않고 기존 404 정책을 따른다.
- 접근 권한이 없는 게시글: 북마크 여부를 노출하지 않고 기존 권한 오류 정책을 따른다.
- 중복 추가 요청: 유니크 제약 위반을 사용자 오류로 노출하지 않고 북마크 상태로 수렴시킨다.
- 삭제 대상이 이미 없는 경우: 미북마크 상태로 처리한다.
- 목록 조회 실패: 빈 목록으로 오인시키지 않고 오류 및 재시도 수단을 표시한다.

## 11. 인수 조건

- 로그인 사용자가 게시글을 북마크하면 선택 상태가 표시되고 새로고침 후에도 유지된다.
- 같은 사용자가 같은 게시글을 여러 번 추가해도 데이터베이스 행은 하나다.
- 북마크를 해제하면 새로고침 후에도 미선택 상태이며 마이페이지 목록에서 사라진다.
- 마이페이지에는 현재 사용자가 북마크한 게시글만 최근 북마크 순으로 표시된다.
- 다른 사용자의 북마크는 클라이언트 요청 변조로도 조회·추가·삭제할 수 없다.
- 비로그인 사용자의 북마크 쓰기 요청은 거부되며 UI는 로그인을 안내한다.
- 추가/해제 요청이 실패하면 UI가 실제 저장 상태로 복원되고 오류 안내가 표시된다.
- 북마크한 게시글이 없을 때 빈 상태가 표시된다.
- 게시글 또는 사용자가 삭제되면 연결된 북마크도 삭제된다.
- 로그아웃 후 직전 사용자의 북마크 데이터가 화면이나 React Query 캐시에 노출되지 않는다.
