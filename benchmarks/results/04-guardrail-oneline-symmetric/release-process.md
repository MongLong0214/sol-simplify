# 릴리스 프로세스

## 목적과 적용 범위

결제 서비스의 운영 환경 변경을 안전하고 추적 가능하게 수행한다. 운영 코드, 인프라, 설정, 데이터베이스 스키마 및 카드소유자 데이터 환경(CDE)에 영향을 줄 수 있는 변경에 적용한다. 모든 증빙은 별도 문서가 아닌 하나의 릴리스 티켓에 링크하거나 첨부한다.

## 역할과 승인 절차

| 역할 | 책임과 승인 대상 |
| --- | --- |
| 릴리스 담당자 | 릴리스 티켓과 체크리스트를 작성하고 배포·검증·기록을 수행한다. 자신의 릴리스를 최종 승인하지 않는다. |
| 코드 리뷰어(작성자 외 1명 이상) | 변경의 정확성, 테스트 범위, 보안상 결함 여부를 검토하고 PR을 승인한다. |
| PCI 보안 담당자 | CDE 범위·카드 데이터 흐름·인증/권한·암호화·로깅 등 PCI 통제에 영향을 주는 변경에 한해 보안 영향과 필요한 보안 테스트를 승인한다. 영향이 없으면 릴리스 티켓의 사유 기록으로 갈음한다. |
| 서비스 책임자(또는 사전 지정 대리인) | 변경 사유와 범위, 장애 위험, 테스트 결과, 관측 방법 및 롤백 가능성을 확인하고 운영 배포를 최종 승인한다. |

승인은 `코드 리뷰 → 해당 시 PCI 보안 승인 → 서비스 책임자 최종 승인` 순서로 받는다. 승인자 이름, 시각, 승인 대상 버전을 릴리스 티켓에 남긴다. 최종 승인 후 코드·설정·배포 계획이 바뀌면 영향받은 테스트를 다시 수행하고 최종 승인을 다시 받는다.

## 릴리스 전 체크리스트

릴리스 담당자는 아래 항목을 모두 확인한다. 해당하지 않는 항목은 `해당 없음`과 사유를 적는다.

- [ ] 릴리스 티켓에 변경 사유·내용, 영향 서비스, 사용자 영향 및 관련 PR/커밋을 기록했다.
- [ ] CDE 및 PCI 통제에 대한 보안 영향과 `중대한 변경` 여부를 기록했다. 중대한 변경에는 CDE의 주요 장비·소프트웨어 교체/업그레이드, 카드 데이터 흐름·저장 방식·CDE 경계, 기반 인프라 또는 관련 제3자 서비스 변경이 포함된다.
- [ ] 작성자 외 코드 리뷰와 필요한 승인을 완료했으며, 승인 후 변경이 없다.
- [ ] CI가 통과했고 단위·통합·결제 흐름 테스트 및 변경에 필요한 보안 테스트 결과를 티켓에 연결했다. 테스트 데이터에는 실제 카드정보를 사용하지 않았다.
- [ ] 설정·시크릿·외부 결제사·작업 큐 등 의존성과 배포 순서를 확인했다.
- [ ] 데이터베이스 변경은 직전 버전과 호환되며, 비가역 변경이면 복구 또는 보상 실행 방법을 준비했다.
- [ ] 배포할 불변 아티팩트의 버전 또는 다이제스트와 직전 정상 버전을 확인했다.
- [ ] 롤백 명령, 예상 소요 시간, 담당자와 롤백 시 데이터 처리 방법을 티켓에 적고 실행 가능성을 확인했다.
- [ ] 카드 승인 성공률, 오류율, 지연시간, 처리량·큐 적체와 결제 스모크 테스트를 즉시 확인할 대시보드·알람이 준비되어 있다.
- [ ] 단계 배포가 가능하면 단계별 대상과 관찰 시간을 정했다. 롤백 기준은 정상 기준선/SLO 대비 수치와 최대 판단 시간(5분 이내)으로 명시했다.
- [ ] 릴리스 담당자와 운영 당번이 배포 시간 동안 대응 가능하다.

## 배포와 확인

1. 릴리스 담당자는 승인된 버전만 배포하고 시작 시각과 배포 도구 실행 링크를 티켓에 남긴다.
2. 단계 배포가 가능하면 소규모 대상부터 배포한다. 각 단계에서 결제 스모크 테스트와 카드 승인 성공률, 오류율, 지연시간 및 큐 적체를 확인한 뒤 다음 단계로 진행한다.
3. 정한 롤백 기준을 넘거나 결제의 정확성·보안에 의심이 생기면 다음 단계로 진행하지 않고 즉시 롤백한다. 롤백 실행에는 추가 승인을 기다리지 않는다.
4. 전체 배포 후 같은 지표와 주요 결제 흐름을 다시 확인하고 종료 시각과 결과를 기록한다.

## 롤백 절차

1. **중지:** 진행 중인 배포와 후속 작업을 즉시 멈추고 운영 당번에게 롤백 시작을 알린다.
2. **복구:** 릴리스 티켓에 지정한 직전 정상 아티팩트·설정으로 되돌린다. 데이터베이스 변경은 사전 준비한 역방향 또는 보상 절차만 실행한다.
3. **확인:** 배포 버전, 결제 스모크 테스트, 카드 승인 성공률, 오류율, 지연시간 및 큐 적체가 정상 기준으로 회복됐는지 확인한다.
4. **확대 대응:** 기준 시간 내 회복되지 않거나 데이터 정합성·보안 문제가 있으면 기존 장애 대응 절차를 호출한다. 서비스 복구를 위해 원인 분석을 기다리지 않는다.
5. **기록:** 롤백 결정·시작·복구 시각, 결정자·실행자, 원인 신호, 실행 명령/도구 링크, 복구 버전, 검증 결과 및 관련 장애 티켓을 릴리스 티켓에 남긴다.

## 감사 대응 기록 항목

릴리스 티켓을 변경 기록의 기준 원장으로 사용하며 다음 항목을 보존한다.

- 릴리스 ID, 변경 사유·설명, 요청자·릴리스 담당자, 예정/실제 시작·종료 시각
- 영향받는 서비스·인프라·설정·데이터베이스와 사용자 영향
- CDE/PCI 통제 및 보안 영향, 중대한 변경 여부와 판단 근거
- PR, 커밋, 배포 아티팩트 버전/다이제스트, 변경된 설정·스키마 식별자
- 코드 리뷰와 운영·보안 승인자의 이름, 승인 시각, 승인 대상 버전
- 수행한 기능·결제 흐름·보안 테스트와 결과, CI/스캔 실행 링크
- 배포 계획, 롤백 기준·명령·예상 시간, 직전 정상 버전
- 배포 도구 실행 로그, 실제 배포 대상·버전, 배포 전후 스모크 테스트와 핵심 지표
- 롤백 여부와 롤백 기록, 발생한 장애·데이터 정합성 문제 및 관련 티켓
- 중대한 변경인 경우 변경된 시스템에서 관련 PCI 통제가 계속 유효함을 확인한 결과와 갱신된 범위/구성 자료 링크

기록은 접근 권한과 변경 이력이 남는 티켓 시스템에 최소 12개월 또는 다음 PCI-DSS 감사 완료 시점 중 더 늦은 때까지 보존한다. 카드번호 전체, CVV 등 민감한 인증 데이터, 운영 시크릿은 티켓·로그·첨부에 기록하지 않는다.
