# 개발 프로세스와 검증 체계

## 전제와 품질 기준

이 프로젝트의 품질은 “버그가 전혀 없음”이 아니라 다음을 지속적으로 증명하는 것으로 정의한다.

- 같은 입력과 실행 조건을 기록해 결과를 재현할 수 있다.
- 러너, 채점기, 벤치마크의 변경이 기존 의미를 몰래 바꾸지 않는다.
- 에이전트가 만든 신뢰할 수 없는 코드를 호스트와 자격 증명으로부터 격리한다.
- 점수에는 과장되지 않은 근거와 정확한 버전 정보가 따라간다.

공개된 예제 태스크는 러너의 정확성을 검증할 수 있지만 모델의 미지 과제 수행 능력까지 증명하지는 않는다. 비교 평가에서 오염되지 않은 성능을 주장하려면 평가자가 별도로 보관한 태스크 팩을 입력해야 하며, 이 프로젝트가 공개 태스크만으로 그 주장을 대신하지 않는다.

## 개발 흐름

`main`을 항상 실행 가능한 기준선으로 둔다. 혼자 작업할 때는 의례적인 자기 승인 PR을 요구하지 않는다. 변경마다 먼저 사용자에게 관찰되는 동작을 한 문장으로 정하고, 그 동작을 실패시키는 가장 작은 테스트를 만든 뒤 구현한다. 문서나 내부 정리처럼 동작이 바뀌지 않는 변경에는 억지 테스트를 추가하지 않는다.

커밋 전에는 변경 범위에 해당하는 테스트를 실행하고 diff에서 점수 의미, 실행 권한, 결과 형식의 의도치 않은 변경만 확인한다. `main` 반영 시 단일 CI 워크플로가 전체 검증을 수행한다. 외부 기여가 생기면 같은 CI를 PR에 적용하되 별도의 승인 체계나 기여자 등급은 만들지 않는다.

버그는 재현 가능한 경우 먼저 회귀 테스트로 고정한다. 한 번의 실수 때문에 새 문서나 전역 규칙을 추가하지 않는다. 기존 검사가 제품 동작과 무관하게 실패하면 예외 절차를 만드는 대신 그 검사를 수정하거나 삭제한다.

## 최소 제품 검증

첫 세로 단면은 작은 샘플 저장소 하나와 성공·실패가 명확한 가짜 에이전트로 `태스크 로드 → 격리 실행 → 채점 → 결과 저장`을 끝까지 수행해야 한다. 이 경로가 동작하기 전에는 플러그인 체계, 대시보드, 분산 실행, 벤치마크 관리 서비스를 만들지 않는다.

CI는 선택한 언어의 포맷/정적 검사와 아래 동작 테스트를 한 워크플로에서 실행한다. 지원한다고 명시한 운영체제나 런타임만 행렬에 넣는다.

| 변경 영역 | 반드시 증명할 동작 |
| --- | --- |
| 러너 | 정상 종료, 실패, 시간 초과, 취소, 하위 프로세스 정리, 로그·산출물 보존 |
| 채점기 | 알려진 정답/부분 성공/실패 벡터, 경계값, 중복 결과의 이중 계산 방지, 입력 순서가 무의미한 곳의 순서 불변성 |
| 태스크 형식 | 필수 필드 거부, 알 수 없는 버전 거부, 고정된 샘플 저장소에서의 기대 결과 |
| 격리 | 작업 디렉터리 이탈, 경로 순회, 명령 인자 주입, 호스트 자격 증명 접근, 금지된 네트워크 접근 차단 |
| CLI·패키지 | 깨끗한 임시 디렉터리에서 설치 후 샘플 평가를 완료하고 기계 판독 가능한 결과를 출력 |

코드 커버리지는 빈 구간을 찾는 참고 자료로만 사용하고 고정 퍼센트를 합격 조건으로 두지 않는다. 스냅샷 테스트는 사람이 의미를 확인하기 어려운 대형 출력에 쓰지 않고, 안정된 사용자 출력이나 결과 스키마에만 제한한다.

## 평가 신뢰성

태스크는 버전이 있는 데이터로 관리한다. 각 태스크에는 식별자, 입력 저장소 스냅샷 또는 해시, 허용 도구와 네트워크 정책, 종료 조건, 채점기 버전이 포함된다. 이미 배포한 태스크나 채점 의미를 수정할 때는 같은 버전을 덮어쓰지 않는다.

각 실행은 최소한 다음 provenance를 결과와 함께 저장한다: 도구·태스크·채점기 버전, 에이전트와 모델 설정, 프롬프트 또는 그 해시, 입력 저장소 해시, 시드가 있다면 그 값, 실행 환경, 시작·종료 시각, 종료 상태, 점수와 근거 산출물. 비밀 값과 원문 자격 증명은 기록하지 않는다.

에이전트는 매 실행마다 새 임시 작업공간에서 시작한다. 호스트 자격 증명은 전달하지 않고 네트워크는 태스크가 명시적으로 요구할 때만 허용한다. 시간·프로세스·저장공간 제한과 전체 프로세스 트리 종료는 실제 악성 샘플을 사용한 통합 테스트로 검증한다. 플랫폼 격리가 제공할 수 없는 보안 수준은 문서와 결과에 그대로 밝힌다.

에이전트가 확률적으로 동작하면 개별 실행 결과와 시행 횟수를 함께 보존하고, 집계값만 제시하지 않는다. 동일 조건 재실행의 차이는 숨기거나 자동 재시도로 지우지 않는다. 결정적이어야 하는 러너와 채점기에서 차이가 나면 결함으로 취급한다.

## 변경과 릴리스

점수 의미, 태스크 형식, 결과 스키마가 호환되지 않게 바뀌면 해당 버전을 올리고 릴리스 노트에 사용자 영향을 설명한다. 리팩터링만으로 버전을 올리거나 별도의 결정 문서를 만들 필요는 없다.

릴리스 전에는 깨끗한 환경에서 배포 산출물을 설치해 샘플 평가를 한 번 끝까지 실행하고, 그 산출물과 소스 태그가 같은 커밋을 가리키는지 확인한다. 공개한 태그와 벤치마크 버전은 덮어쓰지 않는다. 실패한 릴리스는 수정 버전으로 교체한다.

검사는 실제로 잡는 사용자 영향 버그가 있을 때만 유지한다.
